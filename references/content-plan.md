# Content plan — the page's substance (do this BEFORE building)

A thin page is the #1 failure. Write this outline first; a section needs **a claim, real detail, and a value** — "an icon + one line" is not a section.

## Density floor (every page)
- **≥ 3 substance sections** between hero and footer (aim 3–5), **plus** social proof, **plus** a mid-page CTA band.
- Each substance section: a **headline** (a claim, not a label) + **2–3 sentences of real copy** + **≥ 1 concrete number/spec** + **its own figure** (see `illustration.md`).
- Real data everywhere: numbers, dates, units, names, prices. Never "lorem", never "高性价比" with no number.
- No two sections may share the same layout (alternate art-left / art-right, plain / tinted).

## Templates by product type (adapt, don't copy)
**SaaS / B2B**
`hero(claim+CTA+product console)` · `problem→solution` · `how it works (3 steps, each with a mini-figure)` · `capabilities (2–3 with real metrics)` · `integrations/security` · `customer proof (logos+quote+numbers)` · `CTA` · `footer`

**Consumer app**
`hero(claim+CTA+phone mockup of the REAL screen)` · `core experience 1 (mockup)` · `core experience 2 (mockup)` · `core experience 3 (mockup)` · `reviews (stars+quotes+app-store)` · `CTA band` · `footer`
(app rules: one screen mockup per section; each screen shows real data — a score, a chart, a list.)

**E-commerce / physical product**
`hero(product illustration + price/CTA)` · `the product (spec sheet + detail figure)` · `how it's made / what's inside` · `ritual / how to use` · `reviews + stats + press` · `CTA` · `footer`

**Developer tool / API**
`hero(claim+CTA+endpoint chip+live console)` · `how it works (pipeline)` · `capabilities (latency, limits, models)` · `pricing` · `docs/quickstart` · `proof` · `CTA` · `footer`

**Content / editorial**
`hero(claim+CTA)` · `featured pieces (3 cards)` · `topics` · `about/method` · `newsletter CTA` · `footer`

**Marketplace / community**
`hero(claim+search+CTA)` · `how it works` · `featured listings (cards with real data)` · `trust/safety` · `testimonials` · `CTA` · `footer`

## Writing real copy (not filler)
- Headline = an opinion or outcome ("把夜晚还给你"), not a noun ("睡眠功能").
- Body = the mechanism + a number + an objection handled ("48h 内现烘寄出，可随时暂停").
- Avoid adjectives without evidence; replace "很快" with "121 ms 首字延迟".
- Button labels are verbs + value ("免费领取 Key"), not "了解更多".

## Illustration per section
- App → a **different screen mockup per section** (report · mixer · breathing · stories).
- Physical → the object + a **detail/label card**.
- Abstract → a **console panel** with live-looking values.
Each figure carries real data; figures share one palette + one repeated motif.
