# Directions: propose 2–3, then commit

Source: huashu-design (先出多个方向) + hallmark (catalog of themes/macrostructures).

## When
At Phase 2, when there is **no existing `system.md`**. Variety lives here — once a direction is chosen, hold it (consistency > novelty inside a project).

## How
1. From `themes/catalog.md`, pick **2–3 categorically different** directions (not 3 recolors). Differ on layout family, color treatment, and emotional angle — not just hue.
2. For each, give:
   - a name (e.g. "Editorial / 编辑排版"),
   - palette: 4–6 named hex/oklch values,
   - type: 2–3 faces with roles,
   - layout concept: one sentence + a tiny ASCII sketch,
   - the one-line "why it fits this product".
3. Let the user pick. If autonomous, pick the strongest and state why.
4. **Write the choice into `system.md`** (Phase 3–6). All later work defers to it.

## Constraints
- The signature element must be unique to the product, not a template motif.
- Avoid the three default attractors unless the brief points to them: (a) near-white + high-contrast serif + terracotta; (b) near-black + one acid accent + mono; (c) broadsheet hairline columns.
- Directions must still pass every gate; a "loud" direction is not an excuse for broken spacing/contrast.

## Redesign variant
When redesigning an existing site, run audit-first: extract the current system, name what to preserve vs change, then propose directions that respect the brand equity.
